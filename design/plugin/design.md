# 服务端插件设计

## 1.架构

- 服务端插件位于 OSG 核心之上，用于扩展控制面能力。
- OSG 核心负责 runtime、session、workspace 的基础模型、路由和生命周期管理。
- 服务端插件负责把这些基础能力组织成可用的控制面。
- 插件之间彼此独立，通过统一的宿主接口接入 OSG。
- 插件可以面向不同控制域扩展，例如 runtime 控制、session 桥接、调度、外部网关接入。

## 2.功能

- 为 OSG 提供可扩展的控制面。
- 将不同能力按插件边界拆分，降低核心与业务能力的耦合。
- 为外部调用方提供统一入口，而不是暴露客户端内部细节。
- 支持围绕 runtime、session、workspace、permission、question、mailbox 等对象构建控制链路。
- 允许同一套 OSG 核心在不同部署场景下按需组合能力。

## 3.特性

- 插件化扩展：新增能力时优先通过插件扩展，而不是直接侵入核心。
- 能力隔离：不同控制域可以独立演进和替换。
- 统一接入：外部系统看到的是一致的 OSG 控制面，而不是各客户端私有接口。
- 动态管理：插件支持动态加载、卸载和重载。
- 双形态部署：既支持部署环境的标准安装方式，也支持开发阶段的本地联调方式。
- 面向控制而非托管：插件负责收集状态和下发控制，不替代客户端内部状态机。
