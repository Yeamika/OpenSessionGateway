# 1.核心目标

- 建立统一的 runtime 接入层。
- 建立统一的信息收集、状态监视与控制入口。
- 在不接管客户端内部状态机的前提下，提供统一的跨 runtime 控制能力。
- 通过插件化方式扩展控制面，而不是不断侵入核心。
- 支持以 npm 包为基础的标准化部署与集成。

# 2.模块规划

## 2.1 核心

- OSG 核心负责定义 runtime、session、workspace 等基础对象，以及它们之间的路由关系和运行期模型。
- Session 由客户端托管，OSG 不作为权威存储。
- OSG 对 session 的职责是收集信息、监视状态、路由控制命令，并聚合执行结果。

### 2.1.1 服务器

- 承载 OSG 主服务。
- 提供统一的 HTTP、WebSocket 与控制面入口。
- 负责连接管理、状态汇聚和控制命令分发。

### 2.1.2 传输协议

- 定义客户端与服务端之间的共享消息模型。
- 负责表达 runtime 状态、session 状态、控制请求与结果回传。

## 2.2 插件系统

- 插件系统用于在 OSG 核心之上扩展控制面。
- 核心负责基础模型与路由，插件负责面向具体控制域组织能力。

### 2.2.1 插件sdk

- 定义服务端插件的统一接入模型。
- 为插件提供一致的宿主接口、状态访问和控制调用能力。

### 2.2.2 插件

- 插件负责围绕不同控制域扩展能力。
- 当前重点控制域包括 runtime 控制、session 桥接、permission、question、调度与外部网关接入。
- 在 session 控制域内，后续重点能力包括会话状态增强、异常恢复、上下文压缩与回退恢复。

## 2.3 客户端

- 客户端负责把具体 runtime 接入 OSG。
- 客户端维护真实 runtime、session、permission、question 状态，并响应来自 OSG 的控制命令。

### 2.3.1 客户端库

- 提供连接、日志、协议收发和基础运行能力。
- 作为具体客户端实现的通用基础层。

### 2.3.2 各客户端实现

- 面向不同 runtime 提供具体接入实现。
- 负责状态上报、控制命令执行和能力暴露。
- 客户端继续负责 session 的真实执行、压缩、回退与继续原语，OSG 只负责统一控制入口与状态观测。

### 2.3.3 前端

- 提供 OSG 的展示界面与交互入口。
- 面向用户展示 runtime、session、控制面和插件能力的整体状态。
